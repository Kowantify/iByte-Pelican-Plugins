# Decisions

- 2026-10-20 (0.3.0): Expanded the exposition to the full useful Wings/Panel surface after operator request: per-server network rx/tx, disk read/write (bytes since container start), uptime, Wings-side memory ceiling; per-node capacities (memory/disk/cpu + over-allocate percent, allocations total/used, assigned servers), Panel status counts per node, and panel-wide counts (users, root admins, nodes, maintenance nodes, servers by status, allocations, eggs). Sensitive config (environment/egg/mounts/allocations metadata) stays excluded. Gauges avoid the reserved `_total` suffix (`panel_users`, `node_allocations`).
- 2026-10-20 (0.3.0): New simple dashboard (17 panels): average CPU/memory stats, top-5 CPU/memory nodes, per-server CPU/memory/disk history with limit lines, memory/storage headroom (limit ÷ current), backups per node (count and bytes), network/disk I/O, uptime, state distribution, panel inventory pie. Built and maintained by `scripts/rebuild-dashboard.cjs` (declarative panel list, grid pairing logic).

- 2026-10-20: `AGENTS.md` rewritten from the original open-ended feature spec to the shipped product description (three hard constraints: plugin-native only, one scrape endpoint, key-only admin page). Future agent guidance now binds to what exists, not to the abandoned scope (node selection, Loki, transfer acceptance, etc.).
- 2026-10-20: Re-confirmed the scrape-key boundary by re-running the auth suites: anonymous/unauthorized admin actions 403, wrong-key scrape 401, authenticated render 200 (`hash_equals` against the stored SHA-256, HTTPS transport). Endpoint remains secured after the doc rewrite; no code change was needed.

- 2026-10-20: Final constraint pass: plugin-native only, exactly one scrape endpoint, and an admin page that asks solely for the read-only scrape key. An active key is the enable switch; revoking it stops collection and serving. Fixed 5 s cadence with a 15 s freshness grace.
- 2026-10-20: Export all nodes and game servers from that one endpoint; no per-node selection or DNS pinning. The endpoint serves only the bounded cache and never calls Wings per scrape.
- 2026-10-20: `server_info` carries Panel display name and owner username as labels (value 1). Renames/ownership changes change label sets; history for old label sets persists until Prometheus retention removes them.
- 2026-10-20: Backup metrics are node-scoped aggregates (`ibyte_pelican_node_backups_stored`, `_bytes`) using the Panel's own `nonFailed` scope (not yet completed or completed successfully). Per-server backup rows stay out until proven useful; node totals keep cardinality bounded.
- 2026-10-20: Settings keep a stable `panel_id` and change `generation` only when contents change, so Prometheus labels persist across routine saves while stale snapshots still invalidate.
- 2026-10-19: Keep the first release to CPU, memory, cached game-data disk, state and node health. Console-log ingestion is omitted because Wings' bounded log tail is not a durable cursor.
- 2026-10-19: Run one Laravel sub-minute scheduled command every five seconds. The admin-configured interval gates each node's actual requests. The ordinary Panel scheduler must be running; no browser is involved.
- 2026-10-19: Use the authenticated Wings `GET /api/servers` batch, one request per node per cycle; response rows validated against Panel inventory, capped at 1000 per node.
- 2026-10-19: Reuse Panel's encrypted node token strictly inside the Panel process. Prometheus receives a separate revocable bearer secret whose SHA-256 hash is stored locally. No daemon token is sent to Grafana or exposed in metrics.
- 2026-10-19: Prometheus owns history. The Panel stores only the latest per-node snapshot in its shared Laravel cache. The operator must use a shared lock-capable cache for more than one Panel host.
- 2026-10-19: Treat Wings disk values as cached values with unknown source-sample age. The poll time indicates only successful API collection.
- 2026-10-19: Ship a preview until native Linux Panel/Wings, Prometheus and Grafana acceptance gates pass. The optional stack pins version tags and Docker Hub manifest digests, but runtime validation remains a release gate.
