# Installation architecture

Preview.14 uses native Pelican services and stock Wings, with the official Pelican Modrinth plugin as the repository-integration reference. The user explicitly superseded the original exclusive-fence restriction. No Panel core or Wings patches, downloaded host executables, Blueprint layer or node addon are shipped.

## Pipeline

1. Browser selection supplies only provider/project/release IDs and context. Server-side adapters resolve exact immutable metadata and produce an expiring plan digest plus server/profile/policy fingerprint. Tenant and native permission checks cannot be supplied by the browser.
2. Confirmed Install claims the unique per-server operation slot and queues a UUID-only job plus an install flag. A dedicated database/Redis connection has a 1860-second reservation; `minecraft-manager:work` uses a 1800-second timeout. Readiness-only jobs remain distinct and never install content.
3. The worker reauthorizes the original actor and checks original server/node, policy, plan digest, fingerprint, expiry and fresh release metadata. The native node state must be exactly offline, with no transfer or suspended/installing status.
4. Stock Wings pulls provider payloads into temporary sibling files, at most three concurrently. Validate public HTTPS hosts, redirects and DNS without forwarding API credentials to artifacts. Bounded node readback verifies size and publisher hashes. Archive inputs also receive private bounded inspection on the Panel before native node extraction; downloaded Java never executes on the Panel. MCJars only supplies HTTPS/size in sampled recipes; calculated SHA-256 is a transfer checksum, not independent authenticity proof. Reject unsafe archive paths, special files, collisions and excessive expansion.
5. Resolve dependencies, exact manifest Minecraft/loader requirements and supported recipes. Select a Java image from the egg's allowed images/current server image. Preflight existing server-local runtime variables with native validation before bulk content download. Plugin JAR inspection checks declared platform descriptors and entry-point Java headers when the image identifies its Java major. Egg mapping controls availability, never runtime selection or catalog coverage.
6. Reauthorize and check stopped state repeatedly. Verify prepared content and build the ownership journal. Runtime files finish in normal locations, including server.jar, libraries/, mods/ and plugins/. Archives require temporary root ZIP files and validated native extraction. Existing raw entries are temporarily moved/restored; temporary siblings and newly empty directories are removed. No generated manager directory is created. Capture verified original recovery bytes privately on the Panel before changing live targets.
7. Persist the journal before live replacements. Compare target hashes again, promote verified siblings and verify outputs. Retire only unchanged obsolete plugin-managed files. Apply startup/image and managed type/version/build/JAR variables through the native service and node sync. Merge fresh unrelated variables to preserve JVM/memory settings; retain a compatible existing server.jar command. Verify final files/settings, then atomically record inventory/runtime metadata and success in the Panel database. Remove private recovery copies after success.
8. On handled failure, restore original bytes/startup/managed variables only when current state is recognizably ours. Preserve unrelated edits; ambiguous managed edits leave `needs-reconciliation` and the reservation. A console command verifies or restores recorded original files/settings before releasing the slot. Safe rollback removes private copies; interrupted/unsafe recovery retains them. Hard-killed active phases must age beyond 31 minutes before reconciliation. Exceptional recovery can upload original private bytes to Wings; normal provider installs never upload payloads from the Panel.

## Preservation and boundaries

World data, server.properties, admin lists, EULA and arbitrary manual additions are not pack replacement targets. Existing configuration is preserved. Only tracked unchanged obsolete mods/plugins/runtime libraries are removed with private original-byte recovery. Old recorded node backups are exported and hash-verified on the next install; unrecognized/changed files are retained. Durable private recovery storage must be available to every worker in a multi-host Panel deployment. Preserving worlds does not convert world formats or make Minecraft downgrades safe.

No exclusive guarantee spans stock Wings Files/SFTP/power operations. The plugin's DB slot only coordinates plugin operations. Hash comparison and offline checks are repeated but cannot eliminate races from external actions. Operators must leave the server stopped and avoid concurrent edits. Installation success means verified files, not Java boot or application health.

No implicit EULA acceptance, automatic start, pack bootstrap script execution, arbitrary URL input or substitution of a different requested build is used. When CurseForge omits a download link, its exact public CDN file can be resolved from matching API file/project IDs and filename only with a positive declared size and publisher SHA-1. Ordinary public-host, redirect, size and hash checks still apply; API credentials never reach the CDN. Denied files remain failures. Server-required Modrinth resource/shader files and configuration world templates are accepted within bounded content roots; live root worlds are excluded.

## Catalog and live status

Installed runtime tracking supplies removable package filters; explicit existing startup variables supply a configured fallback. External managed-variable edits invalidate stale tracking. Defaults refresh when the runtime changes, while user-cleared filters survive provider, sort and tab changes. Modpacks are not filtered by the current runtime. Directional plugin platform rules apply consistently to search, releases, dependencies and final reviews; proxy software versions do not become Minecraft version filters.

The authorized child status component polls every two seconds and selects only display fields from operation journals. It reports actual Wings fractions, checked file counts, installation phases and terminal results without rerendering the catalog. Parent pages do not poll, and recent results are collapsed instead of requiring a separate Activity tab.
