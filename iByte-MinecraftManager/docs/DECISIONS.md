# D025 — Install in normal directories without a manager work folder

The user does not want `.minecraft-manager` in their server volume. Stock Wings scopes filesystem operations to that volume and extracts entire archives relative to the supplied directory. Its backup restore restores the archive as a whole; it does not expose an arbitrary off-volume scratch filesystem or selective archive extraction. Native source was checked before this change. Hiding the old directory in the Panel would leave it visible through SFTP and would not implement the requested layout.

New installs use temporary sibling `.part` files for downloads and final native renames into mods/, plugins/, server.jar and validated runtime/content paths. A temporary root ZIP is required for archive-based releases. Paths, checksums, expansion limits and CRCs are checked before native root extraction. Raw archive entries are recorded before extraction; existing entries are temporarily renamed and restored using native moves, selected files are moved beside their final destination, unselected extracted files are removed, and newly created empty directories are pruned. No generated extraction directory is created. Short-lived temporary files and provider archive directories may be visible during unpacking; successful completion leaves normal server content only.

Old bytes and their SHA-256 values are captured in storage/app/minecraft-manager-recovery/<operation UUID>/ on the Panel before a live change. New payloads never upload from the Panel; exceptional rollback may send original recovery bytes back to Wings. Handled success or safe rollback removes private copies. Interrupted/unsafe recovery retains them and the operation reservation. Shared Panel deployments need the same durable private storage available to the recovery worker. Worker-failure handling covers preparation as well as final replacement. All recovery paths are checked before mutation, and concurrent edits are preserved.

Legacy cleanup exports only exact recorded backup paths for terminal operations with matching server/node identity, verifies private copies against recorded hashes, persists their new location, and then removes the old node copies. Empty-directory pruning cannot delete unrecorded files or follow symbolic links. Unrecognized or modified legacy files are retained. This supersedes D024's remote staging directory and indefinite node backup retention. Verification passes ten real server layouts, five legacy export assertions, actual private-copy rollback and three final-ZIP queued pack reinstalls. Evidence is in docs/evidence/live-direct-destinations; production-host and arbitrary-release behavior remain unverified.
Large-pack verification exposed repeated loading/decoding of the growing journal. Per-file authorization now selects only id/status/server_slot, and final verification decodes the plan only when publishing progress. Server/admin parent pages no longer fetch unused full operation lists. The independently authorized progress feed selects only display fields through Laravel JSON selectors and reconstructs its read-only presentation; it never hydrates recovery journals. A native regression verifies displayed fractional progress with a 1 MiB journal while retaining the original journal in the database. These changes do not relax node, permission, checksum or rollback checks.

Further real-node measurement found that checking existence by listing a directory containing thousands of entries cost about 40 ms per request, while reading the small target for its checksum cost about 1 ms. Metadata is now collected once per parent for a group of paths. Temporary-name collision checks and expected-byte checks use fresh checksum reads; only authenticated HTTP 404 means absent, and other failures propagate. Recovery still rejects nonregular files and symbolic links. Eleven native HTTP contract checks cover grouped listings, absent parents, fresh hashes and error propagation in addition to the original installer protocol checks. PostgreSQL display selectors explicitly cast the journal's text column to JSONB; native tests compile PostgreSQL/MySQL/MariaDB queries but execute SQLite only.
