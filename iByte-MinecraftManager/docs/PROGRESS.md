## 2026-10-18: research toward removing Panel payload reads

Research only; preview.22 implementation and delivered ZIP are unchanged. User preference is to keep payload download/extraction on stock Wings and avoid routine Panel payload transfers.

- Pelican first-party MinecraftModrinthService.downloadFile uses a foreground Wings pull and checks file existence; this path does not read the downloaded JAR back for a publisher digest. Source: https://github.com/pelican/plugins/blob/main/minecraft-modrinth/src/Services/MinecraftModrinthService.php
- Cosmii02 ModpackInstallService uses Wings pull/decompression, reads extracted manifest/index JSON, merges override directories through native file APIs, and verifies completed files through metadata rather than a per-payload checksum pass. It has source-specific Panel download fallbacks, so it is not universally Panel-free. Source: https://github.com/cosmii02/pelican-modpackmanager/blob/main/src/Services/ModpackInstallService.php
- itzg ModrinthPackInstaller runs local downloads/extraction in the server environment with configurable parallel downloads; InstallModrinthModpackCommand currently defaults its option to ten. The inspected Modrinth file path passes output path and URL to the fetcher, not the manifest digest, so do not claim it demonstrates publisher-hash validation. Source: https://github.com/itzg/mc-image-helper/blob/main/src/main/java/me/itzg/helpers/modrinth/ModrinthPackInstaller.java and InstallModrinthModpackCommand.java in the same directory.
- Another sampled Pelican plugin (nayz19) actually fetches each mod through Panel HTTP and uploads the body to Wings. It does not support a general claim that all other plugins avoid Panel transfers. Source: https://github.com/nayz19/pelican-minecraft-modpack-installer/blob/master/minecraft-modpack-installer/src/Services/ModpackInstallService.php
- Stock Wings pull supports foreground completion and returned file stat, but has no expected-checksum parameter. Reviewed file routes expose no generic file-hash endpoint. Fetching provider checksum metadata records an expected value, not a digest measured from node bytes. Source: https://github.com/pelican/wings/blob/main/router/router_server_files.go and router/router.go.

Candidate design: direct native pulls with completion/status/size checks, Wings extraction, Panel reads only bounded manifest/index JSON, native node-side recovery, metadata-based inventory explicitly distinguished from hash-verified inventory, and optional deep verification. Removing hash reads changes integrity and modified-file/recovery guarantees and requires replacing current SHA-256-dependent journal logic rather than simply deleting verifier calls. If publisher hashes are required with no Panel payload reads, use an installer inside the native installation-container/egg lifecycle; stock Wings remains unchanged but the installation workflow changes. No comparative installer runtime benchmark was performed in this research turn.
