# 3.0.0-preview.2 validation report

This release is **not production-ready**. It implements and tests additional safety and administration features, but cannot satisfy the requested production gate on the pinned upstream APIs/dependencies. No production system was contacted or changed. Nothing was published to GitHub.

## What changed

- Native Delete/Transfer first prepares a fresh, locked backup through the normal backup service and durable queue. The server remains in place. After verified success, a second password/UUID-confirmed native action within 15 minutes verifies the snapshot and retains only that final source backup. It never stores passwords or deferred destructive callbacks. Failure, pending work, an unknown result, stale completion, changed destination or older locks prevent the transition. A free quota slot is required; preparation never evicts the previous recovery point. Running games remain crash-consistent; use native command/power tasks to stop or flush them first. Servers > Clear final-backup preparation clears an obsolete intent while preserving backups and locks.
- Administrative > More > Repository maintenance runs check/stats/prune on the original node even after the game directory/server has been removed. Approved profile, committed key, generation, captured location, private state and normal concurrency/quarantine checks still apply. Identical requests are rate-limited; unresolved work blocks new maintenance. No snapshots are selected for deletion.
- Administrative > More > Automatic retained maintenance enables daily statistics and weekly integrity check/prune for deleted/transferred source repositories through Pelican's existing scheduler. It is opt-in to avoid unexpected storage I/O; there is no automatic snapshot expiry or repository removal.
- Failed or unverified operations produce sanitized, idempotent persistent notifications for root administrators. Administrative > Needs attention lists recent failures without copying node errors, credentials or request payloads into the browser. Notifications are in Panel, not email/webhooks. They need a working Panel scheduler/queue for catch-up; a completely stopped Panel cannot send its own outage alert.
- Administrative > More > Export backup files supports tar and tar.gz for retained snapshots without a live server. Password-confirmed, actor-bound signed links expire in 60 seconds and are single-use. The original HTTPS node must remain configured. Snapshot/generation/location checks, bounded private staging, engine serialization and byte-for-byte tests apply. Panel deliberately streams these downloads; no archive is deposited in game data. Historical-generation copies use their recovery kit instead.
- Incremental preview versioning: `php scripts/set-release.php 3.0.0-preview.3` updates current source/installation identities together; `--check` verifies consistency. Stable version assignment is refused while production_ready is false. Rebuild both architectures and retain old packages for rollback. The installer checks its release URL against its VERSION rather than a separately hardcoded regex.
- Empty Wings nodes can now pass authenticated node-wide addon readiness without requiring a dummy server. Existing populated nodes still verify a server-scoped route.

The UI retains one **Restic Backups** sidebar entry and three native tabs. Keys/history/destruction/exports/policy stay in Administrative, saved measurements in Stats, server links/details/preparation in Servers. Native Backup Hosts stays basic. Existing Wings/S3 actions continue to delegate to upstream.

## Unresolved production gates and missing requested features

1. The exact public BackupAdapterSchemaInterface still has no restore callback. The isolated proposal in UPSTREAM_API_PROPOSAL.md has not been accepted upstream. The source-pinned internal restore bridge remains preview-only; no Panel core patch is silently installed. Wings lacks a supported full fence for already-open SFTP handles, HTTP file writes, uploads and pulls. SetRestoring alone is insufficient. Fixture restore/rollback tests do not establish production writer safety.
2. Fresh Composer audit finds **CVE-2026-108082 / PKSA-xmwy-rmx5-m7h4** in the pinned Panel's symfony/http-foundation. [Symfony's advisory](https://symfony.com/cve-2026-108082) identifies fixed versions and a follow-up regression fix. The tested Panel dependency lock is not silently rewritten by a plugin; upstream must provide a fixed, explicitly retested dependency set. The earlier zero-advisory report is historical.
3. Final Wings binary audit reports six findings: GO-2026-5932 and GO-2026-5746, GO-2026-5668, GO-2026-5617, GO-2026-4887, GO-2026-4883. Prepared source call-graph audit reports the last two Docker findings; applicability of module-wide binary matches is not waived. Existing Docker module path has no fixed version recorded; migrating its API needs upstream regression work. Restic binary audit reports GO-2026-5932 (OpenPGP module-wide match); self-update is omitted from this build, but this does not turn the audit into a pass. Helper binary audit reports no vulnerabilities. See SECURITY.md and raw evidence. CI publication remains blocked.
4. Full browser ZIP install/update, native restore with competing writers, long-running external cron and worker/node interruption, MariaDB/Redis parallel transactions, distributed failure races and S3/multi-node acceptance remain incomplete. Timed native command/queue backup now passes against real HTTPS Wings/Restic on one local node. The new results close important local gaps, not all distributed ones.
5. **Repository relocation is not implemented.** Exports and recovery kits preserve source data and enable manual recovery, but are not automatic relocation/adoption. A correct implementation needs approved destination credentials, source/destination quiescence, verified snapshot/key transfer, durable reconciliation and rollback. No nonfunctional relocation button or unsafe direct copy is shipped.

## Staging installation

Copy the entire release/Wings Installer folder onto one compatible disposable Wings node and run `sudo bash install.sh --allow-preview --node-id NUMBER`. Import the matching Panel ZIP through Admin > Plugins > Import > Install, then restart the actual queue service after updating code. Configure/link the Restic host with profile default, enable preview only for the disposable host in Restic Backups > Administrative, leave restore disabled, and verify create/download/lock/delete plus native schedules. No manual checksum matching, repository deletion or uninstall is required for normal upgrades. See INSTALL_PANEL.md and INSTALL_WINGS.md for preservation/rollback steps.
