# Decisions

1. Deliver v3.0.0-preview.1 until all AGENTS acceptance gates have evidence. Compiling or mocked tests do not imply production readiness.
2. Pin newest official release candidate tags (Panel and Wings v1.0.0-rc.1). There is no final stable 1.0 release in the fetched tag lists. Do not claim broad version support.
3. Use a clean implementation. Legacy builds target Pterodactyl Wings, use a separate scheduler and mutable owner-derived repository names. Those behaviors will not be copied.
4. No production connections, repository migration, auto-wipe, parallel backup UI or separate scheduler. Repositories use immutable host/node/server identity.
5. Portable local build tools may be downloaded into ignored `.tools` with official checksums. Linux/systemd and browser UI validation must be reported separately if unavailable here.
6. Restore bridge: bind the existing non-final `DaemonBackupRepository` to a plugin subclass. Both actual UI and API use this dependency, while non-Restic restores delegate unchanged. Source hashes gate every Restic operation. This is a preview-only internal compatibility shim, not a supported Pelican restore adapter API. An upstream restore dispatch contract is proposed separately; supported plugin-only production gate remains blocked pending adoption or explicit upstream support plus runtime evidence.
7. Completion uses a durable native queue job polling the authenticated daemon, validates full host/node/server/backup/request identity, updates native backup fields, and emits the existing `BackupCompleted` event. No custom/forged native callback and no guessed callback extension are used. Network ambiguity becomes unknown after a bounded deadline; it is never success.
8. Lock authority stays in Panel. The addon exposes no customer APIs or unlock route and never mutates snapshot tags for locks. The original no-retention/no-prune scope is superseded by decision 27 at the user's explicit request. This avoids Restic `tag` changing immutable snapshot IDs and ensures native lock/quota deletion decisions remain authoritative. Out-of-band root Restic use is outside this guarantee.
9. Credential references only in Panel: actual Restic passwords and S3 credentials stay in mode 0600 node files. No plaintext Panel-host secret storage is introduced. Node profile changes require explicit maintenance; Panel host configuration is immutable once referenced.
10. Restore requires the native truncate confirmation and independently proven stopped daemon state. It stages and verifies before moving any active entries, journals before commit, preserves the root inode for Wings' open UnixFS handle, rolls back normal failures, and preserves the journal/protection on uncertainty. Successful rollback copies are retained until operator review. This is a journaled series of renames, not a filesystem-wide atomic swap or power-loss proof transaction.
11. Preview rejects symlink trees, special files, configured mounts, custom volume roots and relocated nodes. This deliberately limits staging support until Linux isolation tests justify broader behavior. Live backups are crash-consistent only; use native schedule stop/command tasks for application consistency.
12. Never infer a missing S3 repository from a failed network request. Remote repo init is explicit through a root-only helper; a durable provisioning marker is required. Existing repositories are not adopted or wiped.
13. A source audit discovered current HTTP/2 findings in stock Wings' x/net lock. Carry a separate reproducible dependency-only patch from v0.58.0 to v0.60.0 plus sums. Source code still has only one router import and one registration call (passing the manager for startup quarantine). No other Wings services are replaced.
14. govulncheck v1.9.0 still flags two module-wide unreviewed upstream Docker advisories; the published version ranges have no fix on the current module path. Keep this security gate and CI publication blocked; do not migrate to a new Moby major API or suppress findings without upstream/runtime evidence.
15. Force TLS verification in the Restic client even though the native daemon macro disables it outside production. Validate the exact response addon version and token-ID header explicitly; the stock header regex does not cover the pinned prerelease/addon suffix. Other backup schemas retain their original repository behavior.
16. Source inspection proved native restore protection does not fence existing upload JWTs/background pulls/privileged file requests. Therefore native Restic restore defaults to blocked. A separate explicit host toggle permits only isolated disposable fixture testing; it is not production support or a replacement restore UI. This is an additional upstream Wings maintenance-contract gate.
17. The official Restic precompiled runtime had 34 conservative vulnerability matches from an old compiler/dependency lock. Replace it with a central build of exact v0.19.1 source `6aa3a516ce654808a1f28f9fa21e9b7c8e6e90bf`, Go 1.27.2, explicit security-only dependency lock patch and no self-update command. Keep baseline findings, final source/binary scans and module inventory. Normal nodes still receive only precompiled digest-verified executables.
18. The 2026-10-15 host-form failure is a real browser-state bug: native dynamic fields appear without initialized Livewire paths. Use the native `BackupHostResource::modifyForm` extension to initialize only Restic configuration in the schema-change response, rather than remove required validation or patch Panel. Both opt-ins remain false; choosing Restic resets unrelated provider credentials, while opening/editing an existing host preserves its saved values. Include real native Livewire create/edit/re-import regressions and loopback browser evidence. This is a revised **unpublished** preview.1 package; regenerate its ZIP/source/checksums explicitly and supersede the earlier digest report. Existing node binaries and installer stay byte-identical; no Wings reinstall is needed. Published/tagged artifacts must remain immutable.
19. The subsequent create failure was positively identified by the user-provided exception as disabled `staging_enabled`, not CSP or node connectivity. Preserve this guard. Use an explicit HTTP 409 with the exact administrator setting in its safe message so the pinned native action handles it. Supply `Retry-After: 0` because that action reads the header key unconditionally; there is no timed retry or auto-enable. Real native action tests prove no node request or backup/operation record survives rejection; enabled preview still queues without claiming completion. No production access, APP_ENV change, source-hash bypass or restore opt-in change is involved.
20. Queue deserialization failures need actual worker and fresh-process evidence. The native loader resolves the installed class in a fresh CLI boot; worker restart via cache signal alone is not proof of reload. Add separate native producer/consumer process tests with real database queue serialization and no manual plugin loader or fake queue. Recover only the identified failed polling job with its original request UUID; do not change autoload files, mark backups complete or blanket-retry other plugins' jobs. Record user-reported success separately from independently executed local tests. No runtime patch is justified while the correctly loaded fresh worker succeeds.
21. Per the user's explicit installer usability request, normal operators must not compare or enter hashes. Embed the digest of a six-binary node-only manifest during release packaging and verify it and selected executables automatically. Discover adjacent bundle files, ship one ZIP per architecture, and embed the exact GitHub repository/tag URL in CI-generated standalone installers. Locally generated builds have no invented remote URL. Exclude installer/source/bundle ZIPs from NODE-SHA256SUMS to avoid circular hashes; the full audit manifest still covers all files. Trust the initial script/bundle through the project's reviewed distribution channel/HTTPS origin, not a checksum downloaded beside an untrusted script. Keep TLS, bounded verified downloads, preview acknowledgement, stock-binary restrictions, preflight, rollback and explicit node identity. The user's preference supersedes the earlier manual digest-entry workflow; no download-and-execute pipe or verification bypass is introduced.
22. Show Restic creation-time `data_added_packed` in native backup Size cells for both customer and admin; show logical restore bytes in the tooltip and retain logical daemon mapping limits. Label it Added compressed data, not exact exclusive/reclaimable size. Persist metrics separately, backfill older summaries by explicit async stats refresh, and display Unknown where unmeasured. Shared deduplicated chunks cannot be permanently assigned to one snapshot. Cached admin reporting separates logical restores, referenced blob storage, local repository file lengths, estimated dedup, Restic compression and measurement time. S3 physical billing size remains unavailable.
23. Repository passwords remain privileged node profile files; downloads decrypt transparently on the node. Add a root-admin explanation and escrow guidance, not a browser key-disclosure API. Preserve the distinction between profile password and repository key files.
24. Native deletion destroys daemon data before provider callbacks and native transfer only copies Wings backups. Add a pinned early ServerDeletionService binding plus transfer/node-change/model-delete guards, refusing operations while Restic backups or unresolved jobs remain, even in force mode. Require explicit export/removal before proceeding; never silently orphan or migrate repositories. Automatic retained-backup access after deletion and Restic relocation remain missing features; sequential guards do not claim concurrent lifecycle or Linux acceptance.
25. The user's explicit follow-up supersedes decision 23 and the earlier no-reveal/no-repository-inventory exclusions: provide a root-admin View Restic keys resource with former-owner identity/history, exact repository/profile/node/server metadata and snapshot mappings, encrypted key escrow and a separately reauthenticated, audited, single-use key view/kit. Preserve stable UUID filesystem paths. Node credentials may be sent only on the dedicated daemon-authenticated recovery route over verified HTTPS into encrypted Panel escrow; ordinary forms/job/status JSON and logs remain secret-free. Clear credential disclosure is limited to the explicit root-admin reveal/download response. This is the narrow user-authorized exception to AGENTS' earlier blanket no-client-secret/no-returned-JSON policy, not a relaxation for customer backup flows.
26. Supersede decision 24 only for a deliberate root-admin Retain Restic backups and delete server action, confirmed by current password and full UUID. Commit escrow before native daemon destruction; require complete successful-snapshot coverage and no unresolved work, acquire the server row lock/recheck, and skip Restic forget only within a request-scoped context with finally cleanup. Keep ordinary deletion and all repository-transfer guards. Preserve owner/key/snapshot tables without foreign-key cascades and no auto-prune/wipe. Offline recovery uses complete retained repositories into a new empty directory; automatic new-server adoption or legacy v2 import remains unsupported. Full distributed/native Linux acceptance is still a gate.

27. The user explicitly requests automatic quota replacement and hourly/daily/weekly rollup. Bind the exact pinned non-final InitiateBackupService to a narrow Restic-only subclass, retaining native initiation, throttles, queues, schedule flags and all non-Restic semantics. Modify the existing native Backups table through its inspected modifyTable hook to allow authorized manual replacement at capacity and add a retention modal. No Panel core patch or independent scheduler. Default retains newest copies up to native limit; manual replacement needs backup.delete as well as native backup.create. All locked/pending remain protected and counted. Refuse zero/all-protected/over-limit usage, validate readiness/escrow before irreversible eviction, and never select other providers for automatic deletion. Calendar rollup is opt-in per server, authorized/audited with both permissions, uses selected IANA timezone and completed Monday weeks/days followed by remaining hourly slots; newest successful point precedes older tiers. Locks consume capacity, reservations are best-effort maxima, and DST offsets distinguish repeated hours. Saving changes no snapshots; after verified successful native creation, a durable worker recomputes current locks/policy for one native forget per queue turn and skips while a newer create is pending. The full quota case necessarily forgets before creating, so a later create failure cannot recover the evicted point. Cross-system SQL/forget atomicity is not invented: durable same-ID node deletion supports identified retry/reconciliation when SQL rolls back after forget.

28. Add automatic repository pruning as trusted housekeeping after confirmed authorized forgetting, superseding the former no-prune scope while retaining admin-only direct maintenance controls. Queue/coalesce a durable prune ten minutes after snapshot deletion, retain immutable context after deleting its last backup anchor, and use existing authenticated server routes/serialization/provisioning markers. Fixed prune argv includes --max-repack-size 1G and no forget/keep/unlock flags, so Panel snapshot locks remain authoritative. Root admin can queue prune explicitly in native host controls; end users cannot invoke repository maintenance directly. Two-hour node timeout, delayed-work-aware Panel deadline, ambiguous-state quarantine, retries, source pins and protected history apply. Prune can need substantial spare disk/I/O; no dedicated wall-clock maintenance windows, repair or unsafe unlock are introduced. Local real Restic and native mocked-transport tests support staging only; actual Linux/browser/MariaDB/Redis contention remains a production gate.
29. User-reported missing host-node mapping caused native list rendering to call ResticSchema::getDownloadLink and throw before an administrator could manage backups. URL signing is now side-effect-free during native rendering; DownloadController and restore/delete/create execution retain source/permission/explicit-node validation. Missing association produces actionable HTTP 409 when an operation is attempted, without daemon access. Never guess/auto-attach another node or bypass immutable repository identity. Restore only the original host's actual node association via native admin form. Source inspection proves the native PluginResource import action preserves installed metadata and queues InstallPlugin(reinstall:true); uninstall/deleting backups is not an upgrade prerequisite. Native re-import plus the actual reinstall job is tested against populated host/node/backup/lock/operation/retention/encrypted recovery tables; the destructive uninstall guard remains. Tests use the exact PluginStatus enum rather than inventing an isEnabled method, and actual browser/production update remains unverified.
30. User's screenshots now prove missing recovery table `ibyte_restic_repositories` (SQLSTATE 42S02); do not repeat the earlier node-link diagnosis. Uploaded files do not prove native installation completed: pinned PluginService builds dependencies/assets before migrations. Exact live failure stage is unknown. Add explicit root-only native additive repair and a registered CLI command, with table preflight before any Restic node mutation, a renderable missing-schema recovery page and handled native delete notification. Use reviewed plugin migration up() methods after native migrator run to cover already-recorded-but-missing tables, never reset/rollback/drop or edit history. Recreating a missing escrow table cannot recreate keys; active repos need recapture. Scoped native observers keep Wings/S3 independent. User allows discarding these test backups, but repair needs no wiping or production access; pending/unknown records retain reconciliation guards.

31. User explicitly requires exactly two release folders, superseding the earlier loose artifact/architecture-bundle operator layout. `release/Panel Plugin` contains only the ZIP and brief README; `release/Wings Installer` contains only `install.sh`. The latter is a self-contained Bash entrypoint plus deterministic fixed-metadata USTAR/gzip archive of both precompiled target architectures, reviewed inner installer, manifest and licenses. Verify payload before extraction and every binary through the embedded manifest before execution; no network bootstrap/manual digest matching/compiler required. Preserve stock/managed-binary restrictions, preflight, rollback and explicit preview/node ID. Developer source, SBOMs, hashes and intermediate architecture archives move to `.build/release-artifacts`; old extracted artifacts are preserved outside release. CI emits an optional single download ZIP whose only top-level paths are the same two folders. Embedded hashes establish integrity relative to the trusted script, not authenticity of an entirely replaced script. Local extraction/tamper/argument-forwarding tests do not claim real Linux systemd acceptance.
