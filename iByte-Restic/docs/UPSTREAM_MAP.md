## Restore proof and supported-API gate

The actual UI and API each obtain a download link, set `ServerState::RestoringBackup`, and call the same container-resolved `DaemonBackupRepository`. Neither calls the backup schema for restore. Stock Wings validates `adapter` as `oneof=wings s3`; simply returning a tar URL for a Restic schema cannot work. Registering an adapter alone is insufficient.

The plugin binds a subclass from its discovered service provider. Its override checks schema and server identity; Restic requires destructive confirmation and queues an immutable operation. Other schemas call the parent's original method. `scripts/test-panel.php` executes the actual API restore controller and verifies this dispatch, status protection and successful reconciliation with mocked daemon responses. Source hashes also cover the UI caller and daemon repository. This proves the internal path, not official API stability or a real browser/daemon restore.

The public plugin-only requirement can be met mechanically without edits via this shim, but a **supported restore extension contract** does not exist in the pinned Panel. Production readiness remains blocked until upstream supports a narrow dispatch API or explicitly commits to this binding contract, and all native end-to-end gates pass. See `UPSTREAM_API_PROPOSAL.md`; no proposal files are deployed or auto-applied.

## Additional restore safety gate: complete write fencing

Direct source inspection also found that `SetRestoring` is not a global filesystem mutex. `server/power.go::HandlePowerAction` and `sftp/handler.go` honor native protection; normal Panel API users are blocked by `AuthenticateServerAccess`/`Server::validateCurrentState`, and Filament resources use `BlockAccessInConflict`. However, privileged Panel file exceptions, already issued upload JWTs (`router/router_server_files.go::postServerUploadFiles`) and existing background pulls (`router/downloader/downloader.go::Download.Execute`) can write through the filesystem without consulting the addon job lock. No complete write fence is claimed.

This is a concrete blocker beyond the public Panel restore dispatcher: production restore needs a supported Wings maintenance/filesystem fence that rejects new writers and waits for in-flight HTTP/upload/pull/SFTP writes. Adding ad-hoc replacements for all native file routes would exceed the tiny isolated addon design and risk non-Restic behavior. The current restore is only for isolated disposable fixtures with no competing uploads/file tasks. Its tested engine rollback does not prove full native quiescence. Do not promote until this fence and the runtime failure matrix are verified.

- `app/Services/Servers/ServerDeletionService.php::handle` contacts DaemonServerRepository::delete before provider callbacks. An Eloquent deleting event alone is too late. - `app/Services/Servers/TransferServerService.php::handle` creates ServerTransfer in a transaction before JWT/daemon notification. Its private notify filters selected backups to WingsBackupSchema, so Restic repositories cannot transfer through that mechanism. This proves why an existing Restic backup cannot simply be repointed at its destination. - Restic `internal/data/snapshot.go::SnapshotSummary` persists total_bytes_processed/data_added/data_added_packed; `internal/ui/backup/json.go::Finish` emits them. `cmd/restic/cmd_stats.go` raw-data uses unique referenced encrypted blob lengths and uncompressed ciphertext lengths; compression_ratio covers compressed blobs and compression_space_saving covers all referenced blobs. Restore-size counts logical restored contents across snapshots. These facts underpin distinct historical additions, approximate dedup, compression and actual local file totals; none is an exact exclusive per-snapshot disk-size attribution.

## Automatic maintenance without new upstream code

The plugin provider calls Laravel callAfterResolving(Schedule::class) and registers one five-minute native schedule callback. It dispatches unique CaptureRecovery jobs for live Restic repository groups with missing/hour-old escrow or metrics. No second scheduler or upstream cron edit is installed. Mandatory escrow remains in creation before dispatch. Native PollOperation persists measured repository statistics supplied by create/stats/prune and a separate redacted warning when a verified backup lacks accounting. Native completion still emits BackupCompleted; no restore/completion callback was invented. Admin Restic Backups and native customer storage dialogs read this persisted state only.
