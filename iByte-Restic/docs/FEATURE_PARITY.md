# Legacy feature parity and remaining work

Audited actual legacy source at `4ce6c042086f8e359ce5910422e02823b500ec12`, not its design document alone. LEGACY_INVENTORY.md records all tracked files/hashes. The detailed route matrix below preserves the full inventory; its Go/PHP filenames are relative to the code-map domains in ARCHITECTURE.md.

Core replacements implemented locally: native create/status/lock/unlock/delete/tar-download, native schedules/count quotas, calendar retention and delayed prune; encrypted automatic key/owner capture, retained server inventory, cached automatic storage measurements and admin Restic Backups. They are staging implementations, not full production parity.

| Missing or changed legacy feature | Current behavior and recommended action |
|---|---|
| Restore without truncation / merge mode | Current bridge requires native truncate confirmation and stopped isolated fixture. First obtain supported Panel restore dispatch and Wings full write fencing; keep merge restore deferred. |
| Per-server generated credentials and key-version history | Implemented independent random passwords, resumable two-phase v3 upgrade, encrypted automatic history and current-password-confirmed admin views. No destructive regeneration. Actual key-add/retirement and isolation tested with real Restic; Real Linux local key/engine tests pass; remote/distributed acceptance remains required. |
| Final snapshot plus archive/delete | preview.2 first queues a fresh locked native backup and preserves the server. A second confirmed action requires verified recent completion and source snapshot proof before latest-only retention and native delete/transfer. A free quota slot is required; no archive-directory move or automatic destructive continuation. Distributed race acceptance remains incomplete. Legacy archive attempts a final backup and locks/tags the newest snapshot; backup failure can still leave older content archived, so it is not a guaranteed fresh final copy. |
| Archive-by-name / arbitrary orphan repository scan | Current inventory covers captured new-v3 repositories and survives native owner/server deletion. Arbitrary filesystem discovery/adoption and v2 import are excluded by AGENTS; don't add automatic scanning/wiping. |
| SFTP staged tar.zst export / archive formats | Native download remains bounded tar. preview.2 adds root/password-confirmed retained tar/tar.gz export with one-use signed authorization and bounded node staging, streamed through Panel. No tar.zst or archive placed in game files for SFTP retrieval. This is an export feature, not proof that the old addon supported an SFTP repository backend. |
| Separate backup notes and date/cursor controls | Native names/search/list remain; no custom notes/date cursor. Low priority after native browser acceptance; avoid a parallel backup page. |
| Physical repository-size multiplier enforcement | Native count quotas and real measurements replace estimate-based deletion. Intentionally do not delete recovery points to meet a misleading physical-size estimate. |
| Repository unlock/force-unlock/repair and whole-repository delete | Unlock/repair remain excluded. Admin/password-only whole-local-repository force deletion includes locked/unknown/corrupt snapshots and retained deleted/transferred sources. Physical S3 deletion remains missing. |
| Separate legacy backup UI/scheduler/global settings | Replaced by native Backups/Schedules, conditional host settings and one Restic Backups admin area. Do not restore duplicate UI/cron. |

Additional product gaps (not all claimed legacy behavior): automatic cross-node repository relocation, symlink/mount/custom-root support, validated remote S3 lifecycle, SFTP repository backend, exact remote billing size, deep-data checks/maintenance windows, cancellation and assisted unknown-job reconciliation. Restore is fixture-only; current protected-state flags do not fence every in-flight native writer. Unconfirmed transfer remains guarded; native confirmed transfer keeps only the latest source snapshot in recovery inventory.

Production priority is: (1) supported restore/write-fence APIs and dependency findings, (2) full browser installation and distributed MariaDB/Redis/multinode/S3 failure acceptance, (3) verified optional relocation and advanced maintenance. Local amd64 Linux/systemd, real HTTPS native timed backup, isolated restore, final-backup deletion and retained export now pass; these do not prove distributed or competing-writer safety. Packaging alone does not satisfy these gates. See RELEASE_CHECKLIST.md.

Requested extension: independent random server-repository passwords, automatic resumable shared-profile upgrade and protected key-version history are implemented. Native Delete/Transfer warnings enforce latest-successful-only source retention; older locks block cleanup. Native transfer service/callback tests use disposable SQLite/HTTP mocks; actual multi-node repository relocation is deliberately absent. Deleted-repository recreation is automatic for verified absent local repositories: native manual/scheduled creation prepares a new numbered generation and random key on the same host. Prior keys remain password-protected in history with original locations. Queued/retried first creates reuse the prepared generation; older jobs/deletes remain scoped to the old leaf. Existing paths, active/unresolved work and remote provisioning are not bypassed. Native SQLite/Livewire and real Restic create/delete/recreate/restore/copy-recovery tests are recorded in generations-*.txt; Linux/browser/distributed acceptance remains outstanding.
